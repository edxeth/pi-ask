# Live behavior harness

Run from the repository root, outside `pnpm test`. Each case has a fresh Pi process and session. The six original cases plus `interview` use RPC with the in-process auto-answer bridge. The bridge uses the fork `pi-ask:*` or upstream `@eko24ive/pi-ask:*` events, not terminal keys or RPC dialog responses. `subagent` runs `pi -p --mode json`, with `--tools read,ask_user` and `--no-context-files`, matching a background child's print mode and restricted tool list. The fork loads this worktree's `src/index.ts`; upstream installs `@eko24ive/pi-ask@1.2.0` with `npm` into a temp directory (independent of pi settings) and loads it through a temporary copy and `upstream-rpc.ts`, both via `--no-extensions -e`. The adapter gives upstream's TUI-only tool an in-process UI in RPC mode so its started event reaches the bridge. Print mode loads the same temporary upstream copy directly. The temporary copy links only the worktree dependencies and is removed after the batch. The adapter runs only in the harness; the released upstream package remains unchanged. Both extensions can call `ask_user` in print mode but cannot open its UI; the call returns the "Needs user input" result.

The default matrix is the base model (three runs per case per extension) and five report-only models (one run per case per extension). **With twelve cases and both extensions, the default makes 192 model conversations (72 base, 120 report-only), potentially with multiple requests each; it can incur significant provider charges.** Get approval before running paid models. A base-only dry run with `--repeats 1` makes 24 conversations with both extensions, or 12 with one `--modes` value.

```sh
node scripts/behavior/run.mjs --models 9router/cbcn/deepseek-v4.1-flash --modes upstream,fork --repeats 1 --case interview
node scripts/behavior/run.mjs --models 9router/cbcn/deepseek-v4.1-flash --modes upstream,fork --repeats 1 --case subagent
```

For more base-model evidence, use `--models 9router/cbcn/deepseek-v4.1-flash --repeats 5`. Across all twelve cases and both extensions this starts **120 conversations** (plus any internal requests), versus 72 at the default base repeat count. Restrict `--case` for a smaller paid run.

Default: `node scripts/behavior/run.mjs`. Override with `--models provider/id,provider/id`, `--modes upstream,fork`, `--repeats N` (all selected models), or `--case naming` for diagnosis. Each run has a 120-second timeout. Set `PI_ASK_BEHAVIOR_TIMEOUT_MS` for slower providers. Set `PI_ASK_BEHAVIOR_DIR` to change the output directory (default `~/.pi/artifacts/pi-ask/behavior/`). A non-zero exit indicates infrastructure failure (unavailable model, RPC error, rejected bridge answer, timeout, or process failure). Behavioral differences are recorded, not treated as infrastructure errors.

Each JSON record contains model, mode, case, run number, prompt, tool calls, assistant text, and `tokenUsage`: `firstRequest`, `total` (each with billed `input`, `output`, `cacheRead`, `cacheWrite` tokens), and `requestCount`. Usage sums finalized assistant messages only; it does not add `totalTokens` to its components. RPC records also include the bridge trace, `asked`, `questionCount`, `questionTypes`, `recommendations` (with descriptions), `validationErrors`, `followUp` (`bundled`, `plain_text`, `separate`, or `none`), and `configurationDocRead`. These are observations, not automatic pass/fail judgments. Read the trace and text before drawing conclusions.

`subagent` records `asked`, `askCalls`, `questionCount`, `needsUserInput` (the exact noninteractive tool result), `statedAssumption`, and `stoppedForDecision` in both extensions, as well as the tool results. The text flags use simple keyword matching; inspect `assistantText` to distinguish a plan chosen alone from a safe stop. `interview` asks for a first decision, a bundled follow-up round, and a final dependent decision before a `PLAN:` marker. Its `interview` metrics are `askCalls`, `questionCount`, `followUpBundled`, `elapsedBeforePlanMs` (null if no marker), `runDurationMs`, and `runaway` (more than five ask calls). The bridge chooses the first option for each question. Questions and calls are recorded even if the model stops early or keeps asking. Model compliance is not guaranteed.

Three cases measure whether the user can read the explanation of an ask. Before a form, the user reads two things: the assistant message text since their last input (the prompt, or an ask result that is not an error), and the call's `context` argument, which the chat shows above the form. `context` asks the model to read an ADR and then ask about it; `askContext.firstAsk` records the length of that text and of the first ask's `context`, and whether the case's `factPattern` appears in the text, in `context`, or only in the form's questions and options. In `typed-question` and `explain-only`, the bridge types the case's `firstAnswer` as the answer to the first question of the first ask; `askContext.afterFirstAnswer` records the text written after that answer, the `context` of the forms opened after it, and any further asks. `askContext` also counts asks without `context` (`asksWithoutContext`), opened forms with neither text nor `context` (`openedWithoutExplanation`), opened forms whose `context` repeats the text before it (`explainedTwice`: the text holds at least half of the context's word trigrams), and asks that opened no form, such as invalid payloads (`invalidAsks`). `asked`, `questionCount`, `questionTypes`, `recommendations`, `followUp` and the interview metrics count the forms the bridge answered (its `started` events); `validationErrors` keeps invalid payloads. Each record keeps a `transcript` (block order, text, tool calls, ask results) so metrics can be recomputed, and `costTotal`, pi's summed per-request cost.

`grilling-round` gives a skill-style round format that writes each question and its recommended answer as text. `askContext.formQuestions` counts the questions of opened forms, and `askContext.repeatedQuestions` counts those that the text or `context` before their form already asked: a paragraph that starts with the question's number as the form shows it (`Q3`, also when the label is omitted), or at least half of the prompt's word trigrams. A prompt under three words has no trigrams, so only its number can show a repeat. Questions and options belong only in the form, so the expected count is zero.

`--case` accepts a comma-separated list. A model may carry pi's thinking suffix (`anthropic/claude-opus-5-5:high`); RPC runs then set that thinking level before the prompt. `PI_ASK_BEHAVIOR_VARIANT` labels the records (default: the mode), for comparing several worktrees with the same matrix.

No settings file is changed. RPC allows only `read` and `ask_user`; print uses the same allowlist. Both disable discovered skills, prompts, themes, and project context. The harness does not modify the project.
