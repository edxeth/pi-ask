# Ask context is an `ask_user` argument

The user reads the agent's explanation and then answers the `ask_user` form. The form shows only prompts, option labels and descriptions, and it disappears after Submit. In October 2026 session logs, 37% of asks opened with no message text since the user's last input, and 53% for claude-opus-5-5. On Opus 5.5, Sonnet 5.5 and the Fable models, Anthropic's API returns a note that the model writes just before a tool call as a separate thinking block (a "progress update"), so a client that shows only text blocks shows no explanation. Claude Code (issues #75182 and #97504) and OpenCode (#52735) report the same gap.

`ask_user` therefore requires a `context` string, the first property of its schema. `ask_user` draws its own transcript rows (`renderShell: "self"`): `context` renders as Markdown with the padding of an assistant message, above the `ask_user` row, while the call streams. The TUI form opens below the transcript after the call ends, and the answer returns as the tool result in the same turn. A missing or blank `context` is an invalid payload. Guideline 2 puts each question and its options only in the form, and everything that explains only in `context`, not in message text, without restating the questions. Guideline 3 answers a typed question or an explanation request in `context` when the agent asks again, or in message text when it does not.

Live runs of `scripts/behavior/` on 2026-10-30 compared the alternatives. They used the `context`, `typed-question`, `explain-only` and `grilling-round` cases, 3 runs each, on Haiku 5.5, Sonnet 5.5, Opus 5.5, GPT-6 Luna, GPT-6.1 Terra, GPT-6.1 Sol, GPT-6 Astra and GLM 5.3:

- A rule that asked for the explanation as message text left 12 of 87 forms without text, all of them Opus or Sonnet asks right after a tool result. A captured Opus message held the explanation in its second thinking block.
- A refusal that asked for text and a new call fixed none of the 12, because the retry also follows a tool result. OpenCode #52735 reports the same.
- A refusal that told the model to explain and end its turn, after which pi-ask opened the form, left no form without text. It refused 23 asks in 96 runs. Each refusal cost one more model request, showed a cancelled call in the transcript, and returned the answer as a user message in a new turn.
- With `context`, 0 of 110 forms opened without an explanation, and no ask was refused. Compared with the refusal version, the 96 runs made 239 requests instead of 262, wrote 156,200 output tokens instead of 172,409, and cost $2.47 instead of $2.62. 10 forms had message text before them, against 88 of 111. One GLM ask omitted `context`, failed schema validation, and then repeated its message text in `context`.
- In `grilling-round`, whose prompt gives a text format for questions, a first guideline that asked for "what the decision is" as text let the GPT models repeat 64 of 74 questions. The split guideline counted 7 of 150 questions as repeated, and `context` 3 of 151. All 3 are Opus reasons that start with a question number. GLM 5.3 and the base model still write the round only as text.

The base-model gate of ADR 0003 (deepseek-v4.1-flash against upstream 1.2.0, 3 runs of 12 cases) showed the same forms, bundling and plan completion, and forms without an explanation fell from 20 of 39 to 0 of 39. In `tone`, the base model omitted `type: "preview"` in 3 of 18 runs although every option had preview text, so the form hid the previews; upstream and the earlier fork versions did so in 0 of 32 runs. pi-ask now treats such a question as a preview question before schema validation. In 10 more runs, 8 completed (2 ended with provider errors), and all 8 forms showed previews, including one call that omitted the type.

In October 2026, no other coding agent's ask tool has a context field. Claude Code tells the model that the user may see only the question dialog, so each question must stand on its own; that puts the explanation in the form.
