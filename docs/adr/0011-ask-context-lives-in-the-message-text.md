# Ask context lives in the message text

The user reads the agent's message text and then the `ask_user` form, which shows only prompts, option labels and descriptions and disappears after Submit; thinking, tool arguments and tool output are not a reply. Session logs showed forms that opened with no message text since the user's last input in 37% of October 2026 asks, and in 53% for claude-opus-5-5, so users had to answer questions whose context they had never seen. The tool description now states what the user sees, guideline 2 requires the context as message text before every call, and guideline 3 answers a typed question or explanation request in message text first. pi-ask does not refuse a text-less ask at runtime.

The decision rests on a live run of `scripts/behavior/` on 2026-10-30: the `context`, `typed-question` and `explain-only` cases, 3 runs each, on Haiku 5.5, Sonnet 5.5, Opus 5.5, GPT-6 Luna, GPT-6.1 Terra, GPT-6.1 Sol, GPT-6 Astra and GLM 5.3. Forms that opened without text fell from 79% (77 of 97) to 14% (12 of 87). A variant that refused text-less asks (one refusal per user input) reached 13% at 17% higher cost than the text alone: it fired only for Opus and Sonnet, and every retry also lacked text, because the refusal is itself a tool result. A shorter description without the sentence that repeated guideline 2 behaved the same and is the shipped one.

Opus 5.5 and Sonnet 5.5 still send an ask without message text right after a tool result (a file read or a form answer): every such ask in the run, while both wrote text in every reply that ended their turn. A captured Opus message held the needed context in its second thinking block, followed directly by the tool call. Closing that gap needs a mechanism that does not depend on text in a tool-use message after a tool result.
